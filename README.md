# Kubernetes Production Simulation: Self-Healing Architectures & Deployment Strategies

This project simulates a real-world production environment where undocumented microservices must be deployed, stabilized, and optimized.

The focus was on **incident response, deployment strategies, and observability**, applying SRE and DevOps practices to restore reliability and improve system resilience.

---

## Overview

Worked in a Kubernetes-based environment to diagnose and resolve application issues while implementing modern deployment and automation practices using:

- Amazon EKS (Kubernetes)
- Terraform (Infrastructure as Code)
- CI/CD pipelines
- Prometheus and Grafana (observability)

---

## Key Features

### Incident Response & Troubleshooting
Diagnosed and resolved service failures, including unreachable endpoints, misconfigurations, and resource constraints.

### Deployment Strategies
Implemented:
- Canary deployments for controlled feature releases  
- Blue-green deployments for zero-downtime rollouts  

### CI/CD Automation
Designed and implemented pipelines to automate application deployments and improve release efficiency.

### Observability & Monitoring
Introduced monitoring to identify abnormal behavior and detect performance issues across services.

### Performance Optimization
Analyzed resource usage to identify inefficient workloads and optimize system performance.

### System Documentation
Created architecture diagrams to improve system visibility and streamline onboarding for future developers.

---

## Outcome

- Restored **application availability and reliability**  
- Reduced deployment risk through **progressive delivery strategies**  
- Improved operational efficiency with **CI/CD automation**  
- Enabled proactive issue detection with **observability tooling**  
- Delivered a **well-documented, production-ready Kubernetes environment**

---

## Tech Stack

AWS (EKS), Terraform, Kubernetes, Prometheus, Grafana, CI/CD pipelines
